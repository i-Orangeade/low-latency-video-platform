# 简历 Bullet 模板

> 使用原则：只写已经能用代码、命令或测试结果证明的内容；`[待填写]` 必须替换为本人实测数据。三个阶段不是三份同时投递的简历，而是随着项目闭环逐步升级。

## 阶段一：当前版

适用于现在。当前代码已经具备平台骨架、HTTP-FLV 播放、WebRTC/HLS 播放实现、Hook 测试、延迟探针、压测工具，以及固定 commit 的 ZLM QoS 源码补丁。自定义接口已经过源码编译、真实 RTMP 运行、1/10/50/100 路短时压测和服务重启恢复测试；公网 WebRTC 仍需按目标部署环境联调。

- 设计无人机巡检视频平台的媒体面/控制面分层：FFmpeg/C++ 将 RTMP 流推送至 ZLMediaKit，浏览器直接从 ZLM 拉取媒体，FastAPI 负责播放地址、流状态、录像控制及业务数据，避免视频流量经过业务后端。
- 基于 Vue 3、TypeScript 与 `mpegts.js` 实现 HTTP-FLV 播放，并实现 WebRTC SDP/ICE 建链及原生 HLS 分支；统一管理播放器、PeerConnection 和请求取消，Compose 已映射 RTC 8001 TCP/UDP，公网 ICE/NAT 链路仍待按部署环境联调。
- 使用 FastAPI、SQLAlchemy 与 SQLite 实现设备、告警、录像元数据和实验记录接口；为 ZLM Hook 增加入参校验、密钥比较、发布流白名单、设备上下线同步，以及离线告警和录像路径去重测试。
- 封装 ZLM `getMediaList`、`startRecord`、`stopRecord` HTTP API，统一返回播放地址和流状态，并通过 Docker Compose 编排 ZLM、后端和前端。
- 编写 Linux `tc` 弱网脚本和预编码 H.264 多路推流工具；在 8 逻辑核主机完成 1/10/50/100 路短时稳态压测，100 路时 ZLM CPU 平均 198.90%、P95 217.34%、RSS P95 276.56 MiB，抽样流保持 25 FPS 且 DTS 回退为 0，并保留环境、逐样本数据和复现命令。
- 使用 C++17 调用 FFmpeg 解码真实播放 URL，实现同机“源播放时间线→探针收到帧记录”的延迟采样，输出逐帧 CSV 和 P50/P95/P99，并提供离线计算自测；该边界不等于摄像头到显示器的玻璃到玻璃延迟。
- 固定 ZLMediaKit commit 并实现 `getStreamQos` 源码扩展，在流所属 EventPoller 上按窗口采样，输出真实码率、去重帧率、GOP、DTS 回退和读者数；补丁支持配置开关、可复现 Docker 构建、真实 RTMP 运行和百路容量回归。
- 实现基于 `epoll` 的非阻塞 echo server、有界 MPMC 阻塞队列与 H.264/FLV 结构分析实验，提供功能测试及 ASAN/TSAN 构建选项；这些基础实验尚未集成进 ZLM 媒体链路。

可核验文件：`README.md`、`docker-compose.yml`、`backend/app/api/zlm_hooks.py`、`backend/tests/test_zlm_hooks.py`、`frontend/src/components/VideoPlayer.vue`、`scripts/`、`cpp-tools/latency-probe/main.cpp`、`labs/`。

## 禁用表述

- 未实测时不要写“毫秒级”“零延迟”“高并发”“性能提升 X%”。
- 当前可以写“实现 WebRTC 播放逻辑”，但在真实 RTC 端口、ICE 与浏览器联调完成前，不能写“打通 WebRTC 生产链路”。
- 当前可以写清延迟工具的测量边界，不能把“源播放时间线到 ffprobe 帧记录”包装成玻璃到玻璃延迟。
- 可以写“完成一个范围受控的 ZLM 源码扩展”，并必须能解释 `WebApi.cpp → MediaSource → MultiMediaSourceMuxer::addProbe` 的线程归属和测量边界；没有上游合并前不能写“贡献 ZLM 社区”。
- 当前不能写“Hook 完全幂等”：录像路径有唯一约束和并发冲突兜底，离线告警仍是先查后写，没有数据库唯一约束。
